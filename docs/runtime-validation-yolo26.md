# YOLO26 객체·포즈·깊이 통합 검증

2026-10-21, RTX 3050 4GB Laptop GPU / PyTorch 2.9.1+cu128 /
Ultralytics 8.4.182에서 세 모델을 함께 실행했습니다.
원시 측정값은 [runtime-validation-yolo26.json](runtime-validation-yolo26.json)에 있습니다.
이 문서는 이전 YOLOv8 객체 가중치 검증과 구분되는 YOLO26 검증 결과입니다.

## 사용한 모델과 처리

- `yolo26n.pt`: 공식 Ultralytics assets에서 다운로드한 80개 클래스 객체 검출 가중치
- `yolo26n-pose.pt`: 기존 로컬 사람 키포인트 가중치
- `yolo26n-depth.pt`: 기존 로컬 미터 단위 깊이 추정 가중치

객체 감지와 pose는 보정된 같은 프레임을 사용합니다. 깊이 맵은 사람이 없는
프레임에서도 한 번 계산하며, 객체 박스와 얼굴·신체 키포인트가 공유합니다.
일반 객체의 거리는 중앙 깊이 중앙값 × 보정 스케일 × 사선 보정 배율입니다.
얼굴은 기존 눈·귀 거리 비교와 보정을 유지하고, 신체 부위는 기존 키포인트
패치 샘플링을 유지합니다. 깊이 오류 시 재시도와 기존 거리 폴백을 사용합니다.

## 실제 실행 결과

| 항목 | 결과 |
| --- | --- |
| bus 샘플 10회 | 평균 44.93ms, p95 49.88ms, 30개 검출 |
| zidane 샘플 10회 | 평균 39.20ms, p95 40.40ms, 11개 검출 |
| 깊이 공유 | 샘플별 10프레임에서 깊이 추론 정확히 10회 |
| 사람 없는 빈 프레임 | 깊이 추론 1회 실행 |
| 일반 객체 거리 | bus·person·tie에 `distance_source=depth` 반환 |
| 실제 API 호출 | 200, 30개 결과, `/health`에서 세 YOLO26 모델명 확인 |
| 잘못된 이미지 | 400 |
| 깊이 CPU/GPU 복구 | CUDA 오류 주입 후 실제 CPU 추론, 재시도 시각 조정 후 GPU 복귀 |
| 카메라 0 | 640×480, 연속 30프레임, 약 15.27FPS, 깊이 오류 없음 |
| 카메라 2 | 640×360, 연속 30프레임, 약 7.75FPS, 깊이 오류 없음 |
| JPEG·추적 | 실제 카메라 파이프라인에서 정상 출력 |

샘플의 일반 객체 거리 출력 예시는 bus 4.43m, tie 1.30m였습니다.
이는 **모델의 추정 출력 예시**이며 정답 거리와의 오차를 검증한 값이 아닙니다.
기존 크기 표에 없는 tie도 깊이 맵에서 거리를 얻는 것을 확인했습니다.

## 범위와 재현 조건

설치된 Ultralytics의 `assets/bus.jpg`, `assets/zidane.jpg`를 사용했고,
각 영상으로 한 번 예열 후 10회 측정했습니다. p95는 최근접 순위 방식이며
10개 표본에서는 최댓값입니다. 장기 부하나 비행 중 정확도 결과가 아닙니다.
API는 TestClient로 호출했고 백엔드 전송은 기록용 대체 함수를 사용했습니다.
실제 백엔드 데이터는 변경하지 않았습니다. 카메라 프레임은 저장·외부 전송하지 않았습니다.

실제 CUDA OOM을 발생시키지 않았습니다. 예측 경계에 CUDA 예외를 한 번 주입하고
실제 깊이 모델의 CPU 전환·GPU 복귀를 실행했습니다. 실측 거리 라벨이 없어
거리 MAE·검출 정밀도·재현율은 아직 측정하지 않았습니다.

사용 명령:

```bash
uv run --extra vision python tools/camera_ui.py \
  --object-model yolo26n.pt --model yolo26n-pose.pt \
  --depth-model yolo26n-depth.pt --device 0
```
